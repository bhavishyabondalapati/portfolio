# Bhavishya Bondalapati: Portfolio

My portfolio. The default page is a plain, fast, accessible site: experience, seven project "plates"
with measured results first, coursework, a gazetteer of smaller builds, and contact. An optional second
experience, **Walk the Charles** (`/boston`), is a Boston-at-night page drawn live in WebGL: my experience,
featured projects (each with its GitHub link), skills and contact as you scroll. A third, **the sketchbook** (`/sketchbook`), shows nine of my projects as plates in a sketchbook, each with its key result and a link to the code.

## Tools and libraries, and why

| Tool | Why |
|---|---|
| **Next.js 16 (static export)** | The site is plain HTML, CSS and JS served from a CDN: fast, cheap, nothing to attack. |
| **React 19 + TypeScript** | Components for the sections; types catch content mistakes (a missing figure, a wrong link). |
| **three.js (bundled in `public/house`)** | WebGL for the Boston page: the skyline, river, lamps and cloth cards, without writing raw WebGL. |
| **ThreeUI Kage engine (MIT, Meng To)** | The scroll rig and foreground stages the Boston page grew from; credited in `THIRD_PARTY_NOTICES.md`. |
| **Archivo and IBM Plex Mono** | Archivo's width axis gives wide display capitals and normal body text from one file; Plex Mono for map-margin labels. |
| **Python + numpy (scripts/wow)** | Grades the licensed photographs into one night palette and draws the SVG foregrounds in code. |
| **node:test** | Built-in test runner, so there is nothing extra to install. |
| **Vercel** | Static hosting with security headers set in `vercel.json`. |

## Three ways in

- **The plain site** (`/`) is the default for everyone.
- **Walk the Charles** (`/boston`) opens from a button in the hero and in the invitation card after the
  projects. Phones, reduced motion and data saver open its light mode (`?q=low`: lower resolution, no
  shadows). - **The sketchbook** (`/sketchbook`) opens from "Open the sketchbook". Arrows, keys or dragging turn the pages; the glass magnifies; each plate links to its repository.

Both extra pages have a "Back to the plain site" button.

## Setup

```bash
conda create -n portfolio -c conda-forge nodejs=22 -y
conda activate portfolio
npm install
```

Node packages install into the project's own `node_modules/`; the conda environment only
provides Node 22. No API keys are needed. `SITE_URL` in `.env.example` is optional.

## How to run it

```bash
npm run dev
```

Then open http://localhost:3000. For the production build:

```bash
npm run build
npm start
```

`npm start` serves the static site from `out/` at http://localhost:3000.

Open http://localhost:3000/boston for the Boston page.

Tests and type checks:

```bash
npm test
npm run typecheck
npm run build && npm run test:e2e   # the browser click test (needs the built site)
```

`npm run check` runs all of it in order. Turn on the pre-push guard once per clone, so it runs before every `git push`:

```bash
git config core.hooksPath .githooks
```

First time only, download the test browser: `npx playwright install chromium`. To click through the live site instead of the local build: `BASE_URL=https://your-site.vercel.app npm run test:e2e`. Outside addresses (GitHub and so on) are answered with an empty page, so the test works offline and never touches them.

To redo the photographs (needs the licensed originals in `docs/wow-assets/originals/`, which are not in git):

```bash
python3 scripts/wow/grade.py && node scripts/wow-assets.mjs
```

To redraw the sketchbook (needs Python with Pillow and numpy):

```bash
python3 scripts/sketchbook/plates.py
node --experimental-strip-types scripts/sketchbook/build.mjs
```

## How it was built

1. **Content first.** Read every repo's README and wrote `src/content.ts`; tests check that each figure appears in its own results.
2. **The plain site.** Sections, plates, light and dark themes, accessibility (skip link, AA contrast, focus), static export.
3. **A survey-map concept with a 3D flyover** over real terrain was built and later retired in favour of the Boston page.
4. **The Boston page.** Started from ThreeUI's Kage engine, replaced its temple, images, copy and fonts with a night walk on the Charles drawn in code, graded four licensed photographs to one palette, and drew the foregrounds as SVG.
5. **Sharpness and speed.** 1x/2x images, lazy loading below the hero, a pixel-ratio cap of 2, an automatic resolution governor, and a light mode for phones.
6. **Clean-up and launch.** Removed the flyover, the Kage comparison page and its unlicensed font, added credits, ran tests, build, a secret scan and Lighthouse, then deployed on Vercel.

## Key concepts

- **Progressive enhancement.** The plain site is the product; the 3D page loads only when someone chooses it, so the plain site stays fast.
- **Static export.** Everything is built to HTML ahead of time; security headers are set at the host (`vercel.json`).
- **Content as data.** One typed file feeds the page, and tests guard it.
- **Licences.** Every photograph has a clear licence and credit; MIT code is credited with its full notice.
- **Rendering in code.** The scene is drawn with procedural geometry and textures instead of pasted photos, so it stays sharp at any resolution.
- **Adaptive quality.** The page watches its frame time and lowers resolution when needed.
